# Moss Terminal — 需求规格说明 (Spec v2)

## 概述

Moss Terminal 是一个基于 Kitty 重构的、深度融合 AI 的终端交互产品。AI 不是外挂插件，而是终端的原生能力——终端输出的每一行内容 AI 天然可见。最终交付的是一个**终端应用**（而非 CLI 工具），用户运行的就是 Moss Terminal。

---

## 核心模型：交错对话

Moss Terminal 将整个 Kitty 窗口的生命周期视为一个对话。对话中每一条用户消息由多组**命令-输出对**加上一个**问题**组成。

```
对话结构：

  User Turn 1:  [A11→B11] + [A12→B12] + ... + C1
    A1n = 第 n 条终端命令        ($ ls, $ gcc main.c...)
    B1n = 该命令对应的终端输出    (total 42, error: undefined...)
    C1  = 用户对 AI 的提问       (》为什么报错？)
    → A 和 B 是交错出现的，每条命令紧跟着它的输出

  Assistant Turn 1:  D1 = AI 回答

  User Turn 2:  [A21→B21] + [A22→B22] + ... + C2
    → 从上次 D1 后的位置开始，读取新的命令-输出对

  Assistant Turn 2:  D2 = AI 回答
```

**与传统聊天的对应关系：**

```
传统聊天： [User msg] → [AI reply] → [User msg] → [AI reply]
                   ↓
Moss Terminal： [A11→B11←A12→B12←...←C1] → [D1] → [A21→B21←...←C2] → [D2]
                 ↑ 一条用户消息由多组命令-输出和问题组成
```

**增量感知的数学定义：**

```
Turn 1:
  line_index 从 0 开始
  收集 A11→B11→A12→B12→A13→B13 → 遇到 C1（》触发）→ 冻结
  发送 [A11→B11→A12→B12→A13→B13→C1] → 得到 D1
  line_index 推进到 D1 之后

Turn 2:
  line_index 从 D1 之后的位置开始
  收集 A21→B21→A22→B22 → 遇到 C2（》触发）→ 冻结
  发送 [A21→B21→A22→B22→C2] → 得到 D2
  line_index 推进到 D2 之后
```

## 1. User Stories

### P1 — 核心体验

**US-001: 》即触发**
> 作为用户，我在终端里遇到问题，直接输入 `》 为什么报错` 就可以触发 AI，不需要快捷键、不需要切换模式。

**验收**：
- Given 我在终端正常工作
- When 我输入 `》为什么报错`
- Then AI 回答我的问题
- And 不会被当作 shell 命令执行
- And 回答直接显示在终端中（行内模式）

**US-002: 完整上下文自知**
> 作为用户，我希望 AI 知道自己看到了什么——包括我执行的每条命令和对应的输出。

**验收**：
- Given 我执行了 `gcc main.c 2>&1` 并看到了编译错误
- When 我输入 `》为什么报错`
- Then AI 的回答中应提及具体的命令和错误信息
- And 不应说"我看不到你的操作"

**US-003: 对话式增量**
> 作为用户，我多次和 AI 交互。每次交互是同一个对话中的新消息——之前的对话历史在，但新的终端操作被逐条附加到当前消息中。

**验收**：
- Given 第一次交互（A11→B11→A12→B12→C1→D1）
- When 我又执行了 A21→B21（从上一次 D1 后开始）
- And 输入 `》还是不对`（C2）
- Then 发送的上下文是 `[A21→B21→C2]`（从上次 D1 后的增量）
- And 但系统维护完整对话 `[...D1...][A21→B21→C2]`（含历史）

**US-004: 零侵入集成**
> 作为 Kitty 用户，我希望 Moss Terminal 不改变 Kitty 的任何已有功能。

**验收**：
- Given 我使用 Moss Terminal
- When 我执行 Kitty 的任何功能
- Then 所有功能与原生 Kitty 完全一致
- And 性能无差异

### P2 — 增强功能

**US-005: 知识库参考**
> 作为用户，我提问时（如 "如何配置 pacman"），AI 可以搜索我本地的离线文档作为参考。

**验收**：
- Given 我有 Arch Linux 离线 Wiki 知识库
- When 我提问"如何配置 pacman"
- Then AI 应能搜索知识库并给出基于本地文档的回答
- And 这是 AI 主动判断的，不需要我手动指定

**US-006: 工具执行**
> 作为用户，我可以让 AI 执行终端命令、读写文件、搜索网络等操作。

**验收**：
- Given 我在 Moss Terminal 中
- When 我让 AI "查看这个目录的结构"
- Then AI 应执行 `ls -la` 并返回结果

**US-007: 多角色切换**
> 作为用户，我可以为 AI 设定不同的角色（通用助手、Linux 运维、代码审查等）。

**验收**：
- Given 我配置了多个 persona 文件
- When 我切换角色
- Then AI 的行为和回答风格应与所选角色一致

### P3 — 高级功能

**US-008: 多窗口独立会话**
> 作为用户，我在三个 Kitty 窗口中处理三个不同任务，每个窗口的 AI 会话完全隔离。

**验收**：
- Given 窗口 A 在处理 Go 项目，窗口 B 在装显卡驱动
- When 两个窗口同时使用 AI
- Then 窗口 A 的 AI 只知道 Go 项目上下文
- And 窗口 B 的 AI 只知道显卡驱动上下文

**US-009: 一键安装与配置**
> 作为用户，我运行 `moss-setup` 即可交互式完成 Moss Terminal 的安装和 LLM provider 配置。

**验收**：
- Given 我首次使用 Moss Terminal
- When 我运行 `moss-setup`
- Then 引导选择 provider、输入 API key、选择模型
- And 完成后 Moss Terminal 可直接使用

## 2. 功能需求

### FR-001: 安装与配置 (MUST)

**moss-setup 交互式脚本**：

| 步骤 | 内容 |
|------|------|
| 1. 检测环境 | 检查 Kitty、Python、Rust 是否已安装 |
| 2. 选择 Provider | 列出可用 provider（OpenCode、DeepSeek、OpenAI 等） |
| 3. 输入 API Key | 输入 API key（不回显），写入 `~/.config/moss/.env` |
| 4. 选择模型 | 根据 provider 列出可用模型 |
| 5. 配置确认 | 显示完整配置，确认后写入 `~/.config/moss/config.jsonc` |
| 6. 编译/安装 | 应用 Kitty patch、编译 Moss Engine、安装 Kitten |
| 7. 完成 | 提示用户启动 Moss Terminal |

**moss-setup 是一个独立的脚本**，不依赖 Rust 编译链。用 Python 或 bash 编写。

### FR-002: 行内容捕获 (MUST)

Kitty 的 C 层在 `historybuf_add_line()` 处通知 Python 层。

| 字段 | 说明 |
|------|------|
| `line_text` | 行文本 |
| `window_id` | 窗口 ID |
| `history_index` | ring buffer 中的位置 |

### FR-003: 增量上下文 (MUST)

每个 Kitty 窗口维护一个 `line_index`。

```
line_index = 0
每次收到新行：line_buffer 增长，line_index 不变
检测到 `》` 开头：冻结当前 line_buffer → 组装上下文
  → [A11→B11→A12→B12→...→C1]
  → 发送给 Moss Engine
  → 收到 D1 后：line_index = 当前位置
下次 `》`：从 line_index 开始收集新行
```

### FR-004: 上下文缓存优化 (MUST)

继承 MOSS 中已实现的 Reasonix 缓存策略（从 moss/agent/ 移植）：

| 机制 | 作用 |
|------|------|
| Append-only | 对话历史只追加不删除 |
| Cache shape | system prompt + tool defs 的 hash 追踪 |
| Prune | 工具结果剪枝替换 |
| Compact | LLM 摘要压缩 |
| 三层阈值 | soft / snip / compact / force |

所有逻辑在 Moss Engine 内独立实现，不依赖 Reasonix 进程。

### FR-005: Provider 管理 (MUST)

`~/.config/moss/config.jsonc`，JSON 格式（复用引擎原生格式）。

```json
{
  "active_provider": "deepseek",
  "providers": [
    {
      "id": "deepseek",
      "name": "DeepSeek",
      "base_url": "https://api.deepseek.com",
      "api_key": "sk-...",
      "models": ["deepseek-chat", "deepseek-reasoner"],
      "default_model": "deepseek-chat"
    }
  ]
}
```

### FR-006: 行内 I/O (MUST)

**不需要分屏**。AI 交互直接在终端中进行：

```
输入：在当前行输入 `》问题`，按 Enter 触发
输出：AI 的回答直接写入终端（类似命令输出）
      思考过程实时显示（绿色文字）
      回答结束后回到 shell 提示符
```

### FR-007: 角色设定 (MUST)

```
~/.config/moss/personas/
  ├── default.md          # Moss Terminal 原生角色
  ├── linux-admin.md      # Linux 运维
  ├── code-reviewer.md    # 代码审查
  └── custom.md           # 用户自定义
```

### FR-008: 知识库 (SHOULD)

Moss 的配套组件。当用户提问相关问题（如 pacman、systemd、Arch Linux 配置）时，AI 自动搜索知识库作为参考。

- 存储：SQLite + FTS5
- 格式：Markdown / 纯文本
- 默认内容：用户自行下载的 Arch Linux Wiki
- 管理：`添加/删除/搜索` 通过 AI 对话或命令

### FR-009: 多窗口隔离 (MUST)

| 维度 | 隔离方式 |
|------|----------|
| 行内容 | 每个窗口独立的 line_index |
| 对话历史 | 每个窗口独立的 SQLite conversation.db |
| line buffer | 每个窗口独立的 ring buffer 位置 |

### FR-010: 工具系统 (SHOULD)

`run_command` / `read_file` / `write_file` / `grep` / `glob` / `web_search` / `web_fetch` / `kb_search` / `kb_add`

### FR-011: .env 自动加载 (MUST)

`~/.config/moss/.env` 在 Moss Engine 启动时自动读取。

## 3. 边界条件 (Edge Cases)

| 场景 | 预期行为 |
|------|----------|
| 连续快速 `》` 触发 | 第二次的上下文包含第一次后的所有新行 |
| ring buffer 溢出 | line_index 重置，丢失的历史被 compact 补偿 |
| Moss Engine 崩溃 | Kitty 正常运行，对话历史已持久化 SQLite |
| 没有配置 provider | `moss-setup` 引导配置 |
| 大输出（cat 大文件） | 截断到 10MB |
| `》` 被 shell 当作命令 | Kitty hook 拦截 `》` 开头行，不交给 shell |
| 非 fish shell | Kitty hook 在 C 层，与 shell 无关 |

## 4. 成功指标 (Success Criteria)

| 指标 | 目标 |
|------|------|
| `》` 触发到 AI 开始输出 | ≤ 3 秒 |
| 增量截取精度 | 0 误差 |
| 对话隔离 | 三个窗口独立会话互不污染 |
| Moss Engine 空闲 CPU | 0% |
| Moss Engine 内存 | ≤ 50MB |
| Kitty 因 Moss 崩溃的次数 | 0 |

---

## 5. 不做的事 (Out of Scope)

| 功能 | 理由 |
|------|------|
| 分屏 AI 界面 | 行内交互已确认 |
| Reasonix 进程依赖 | Moss 独立运行 |
| GPU 渲染优化 | Kitty 已有 |
| 语音对话 | 终端场景不需要 |
| CLI 工具 | Moss Terminal 是终端应用，不是 CLI |
